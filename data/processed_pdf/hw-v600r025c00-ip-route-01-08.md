### 8.1 BGP4+简介

定义BGP是一种用于自治系统AS（Autonomous System）之间的动态路由协议，常用版本是BGP-4，BGP-4只能传递IPv4路由。针对IPv6的BGP4扩展，通常称为BGP4+。
目的BGP4+用于在AS之间传递路由信息，并不是所有情况都需要运行BGP4+。
以下情况中需要使用BGP4+协议：
● 如图8-1，用户需要同时与两个或者多个ISP相连，ISP需要向用户提供部分或完全的Internet路由。这时可以通过BGP4+路由携带的各种属性来决定到达目的地，走哪一个ISP的AS更为经济。
● 不同组织下的用户之间需要传递AS路径信息。

图 8-1 BGP4+的应用场景以下情况不需要使用BGP4+协议：
● 用户只与一个ISP相连。
● ISP不需要向用户提供Internet路由。
● AS间使用了缺省路由进行连接。

### 8.2 BGP4+原理描述

传统的BGP4只能管理IPv4的路由信息，对于使用其他网络层协议（如IPv6等）的应用，在跨自治系统传播路由信息时就无能为力。
为了实现对IPv6协议的支持，BGP4需要将IPv6协议的信息反映到NLRI（Network Layer Reachable Information）属性及Next_Hop属性中。
BGP4+ 中引入的两个 NLRI 属性分别是：
● MP_REACH_NLRI：Multiprotocol Reachable NLRI，多协议可达NLRI。用于发布可达路由及下一跳信息。
● MP_UNREACH_NLRI：Multiprotocol Unreachable NLRI，多协议不可达NLRI。
用于撤销不可达路由。
BGP4+中的Next_Hop属性用IPv6地址来表示，可以是IPv6全球单播地址或者下一跳的链路本地地址。
BGP4+是利用BGP的多协议扩展属性，来达到在IPv6网络中应用的目的，BGP协议原有的消息机制和路由机制并没有改变。
BGP4+相关原理描述与BGP相同，不再重复描述，具体可以参考《CLI配置指南-IP路由配置》中的“BGP配置”。

### 8.5 配置BGP4+的基本功能

#### 8.5.1 启动BGP进程

前提条件在配置BGP4+的基本功能之前，需完成以下任务：
● 配置接口的链路层协议参数和IPv6地址，使接口的链路协议状态为Up背景信息应用BGP4+实现网络中AS间的通信时，必须先配置BGP4+的基本功能。
启动BGP进程是配置所有BGP4+特性的首要步骤。启动BGP进程时需指定设备所属的AS号。
须知修改BGP的Router ID会导致设备之间的BGP连接重新建立。
操作步骤步骤1 进入系统视图。
system-view步骤2 （可选）使能BGP环路检测功能。
route loop-detect bgp enable该功能开启后，当设备发现BGP路由环路后，会上报告警。但是由于设备无法自动检测环路问题是否被解决，所以用户需要在检查并排除路由环路问题后执行clear route loop-detect bgp alarm命令手动清除BGP环路告警。
步骤3 启动BGP（指定本地AS号），进入BGP视图。
bgp as-number步骤4 （可选）配置BGP的Router ID。
router-id ipv4-address缺省情况下，BGP会自动选取系统视图下的Router ID作为BGP协议的Router ID。系统视图下的Router ID选择规则，请参见《命令参考》。
当两台设备的Router ID不相同时，可以建立IBGP或EBGP连接。当Router ID相同时，只能建立EBGP连接。
说明如果网络中BGP设备的Router ID是物理接口的IP地址，当IP地址发生变化时，会引起路由的振荡。为了增加网络的稳定性，建议将Router ID手工配置为Loopback接口的地址。
如果设备上不存在配置了IPv4地址的接口，需要配置本设备的Router ID。

步骤5 （可选）中断所有BGP4+对等体的协议会话。
shutdown在系统升级、维护过程中，为了防止在配置过程中BGP4+路由频繁震荡对网络的影响，可以中断所有BGP4+对等体的协议会话。
须知待升级或维护完成后，请执行undo shutdown命令恢复BGP4+对等体的协议会话，否则BGP4+功能无法正常运行。
步骤6 （可选）配置BGP4+内存保护。
prefix memory-limit步骤7 （可选）配置在邻居状态由Down到Up时将BGP4+路由的优先级调整为最低优先级。
advertise lowest-priority all-address-family peer-up [ delay delay ]应用于路由延时发布场景，解决回切场景丢包时间长的问题。如果没有配置advertise lowest-priority all-address-family peer-up 命令，邻居建立后会马上发送携带正常属性的路由。如果配置advertise lowest-priority all-address-family peer-up命令，当邻居建立后，先发送MED值最大和LocalPref值最小的路由，等定时器超时后才发送携带正常属性的路由。
说明reset bgp advertise lowest-priority all-address-family peer-up命令用来在邻居状态由Down到Up时将BGP4+路由的优先级恢复为正常优先级。
步骤8 进入IPv6单播地址族视图。
ipv6-family unicast步骤9 （可选）配置BGP把发布给邻居的路由改为最低优先级。
advertise lowest-priority on-startup [ delay-time time-value ]设备在重启之后，在ARP表项下发期间，该设备发布的BGP路由需要保持低的优先级来防止流量丢失。这时可通过在设备重启前配置advertise lowest-priority on-startup命令把发布给邻居的路由改为最低优先级，即MED值改为4294967295，Local_Pref值改为0。如此，可保证在设备重启后该设备发布的BGP路由优先级降为最低。在ARP表项下发完成后，可通过配置reset bgp advertise lowest-priority on-startup命令来恢复该设备发布路由的优先级。
用户也可以在设备重启前配置advertise lowest-priority on-startup delay-time time-value命令，如此可保证在设备重启后，在配置的延时时间内，设备发布的路由在同类路由中优先级降为最低。ARP表项在延时时间内下发完成，待延时时间结束后，自动恢复该设备发布路由的优先级。在延时时间内，也可通过配置reset bgp advertise lowest-priority on-startup命令用来恢复该设备发布路由的优先级。
说明若advertise lowest-priority on-startup命令不是首次配置BGP功能时配置，配置后不会立即生效，在保存配置并执行reboot命令后才能生效。若advertise lowest-priority on-startup命令是首次配置 BGP 功能时配置，此时配置立即生效。
步骤10 （可选）配置设备重启后将BGP4+路由延迟发布。
advertise delay on-startup delay-time time-value

advertise delay on-startup delay-time命令配置后不会立即生效，在保存配置并执行reboot命令后才能生效。
设备在重启之后，在ARP表项下发期间，该设备发布的路由需要延时发布来防止流量丢失。这时可通过在设备重启前配置advertise delay on-startup delay-time命令配置设备重启后BGP4+路由延时发布。如此，可保证在设备重启后要等待指定的延时时间超时后才能发布BGP4+路由。在ARP表项下发完成后，可通过配置refresh bgp all export命令、refresh bgp ipv6 all export命令或reset bgp advertise delay on- startup命令用来恢复BGP4+路由立即发布功能。
步骤11 （可选）配置BGP单播私网路由不上送到BGP VPNv6。
vrf-route-distribute vpnv6 disable缺省情况下，允许BGP单播私网路由上送到BGP VPNv6。在使用EVPN替代L3VPN的场景中，默认情况下BGP单播私网路由依然会复制到BGP VPNv6，占用系统资源。使用此命令行可以关闭向BGP VPNv6路由表复制BGP单播私网路由，节省系统资源。在L3VPN场景中，配置该命令，BGP单播私网路由将无法交叉到BGP VPNv6，请谨慎配置。

#### 8.5.2 配置BGP4+对等体

背景信息由于BGP4＋使用TCP连接，所以在配置BGP4＋时需要指定对等体的IPv6地址。BGP4＋对等体不一定就是相邻的设备，利用逻辑链路也可以建立BGP4＋对等体关系。为了增强BGP4＋连接的稳定性，推荐使用Loopback接口地址建立连接。
属于同一AS的设备之间配置IBGP对等体，属于不同AS的设备之间配置EBGP对等体。
操作步骤
● 配置IBGP对等体请在需要建立IBGP对等体的设备上进行下列配置。
a. 进入系统视图。
system-view
b. 进入BGP视图。
bgp as-number
c. 配置对等体的IPv6地址及所在的AS。
peer { ipv6-address | group-name } as-number as-number所指定对等体所属的AS编号应该和本地AS号相同。
所指定的对等体的IPv6地址可以是以下四种：
▪直连对等体的接口IPv6地址。
▪路由可达的对等体的Loopback接口地址。
▪直连对等体的子接口的IPv6地址。
▪直连对等体接口的链路本地地址（Link-Local）。

d. （可选）指定建立TCP连接的源接口和源地址。
peer ipv6-address connect-interface { interface-name | ipv6-source-address | interface-type
interface-number | interface-name ipv6-source-address | interface-type interface-number ipv6-
source-address }
peer group-name connect-interface { interface-name | ipv4-source-addr | ipv6-source-addr |
interface-type interface-number | interface-name ipv4-source-addr | interface-name ipv6-source-
addr | interface-type interface-number ipv4-source-addr | interface-type interface-number ipv6-
source-addr }
通常情况下，BGP4+使用与邻居直连的物理接口作为TCP连接的会话接口。
为了提高BGP4+连接的可靠性和稳定性，可将BGP4+连接所使用的本地接口
配置成Loopback接口，这样当网络中存在冗余链路时，不会因为其中某个接
口或链路的故障而使BGP4+连接中断。
e. （可选）配置对等体仅侦听连接请求，而不主动发送连接请求。
peer { ipv6-address | group-name } listen-only
此命令配置后会导致已经建立的peer关系中断，本端等待对端发起连接请求
后重新建立peer关系。通过配置可以避免连接请求冲突的现象发生。
说明
该命令只可在对等体间的一端配置，若两端都配置该命令，则该对等体间的连接不能
成功建立。
f. （可选）配置指定对等体的描述信息。
peer { ipv6-address | group-name } description description-text
为了便于网络管理，可以给指定对等体添加描述信息。
g. 进入IPv6单播地址族视图。
ipv6-family unicast
h. 使能IPv6对等体。
peer { ipv6-address | group-name } enable
在BGP视图下配置BGP4+对等体之后，还需要在IPv6单播地址族视图使能该
对等体。
说明
如果需要短暂中断邻居会话且该邻居配置较多时，可以执行命令peer ignore禁止与对等体
建立会话，避免重新配置的工作量。
● 配置EBGP对等体
请在需要建立 EBGP 对等体的设备上进行下列配置。
a. 进入系统视图。
system-view
b. 进入BGP视图。
bgp as-number
c. （可选）允许相同Router ID的对等体之间建立EBGP连接。
router-id allow-same enable
d. 配置对等体的IPv6地址及所在的AS。
peer { ipv6-address | group-name } as-number as-number
所指定对等体所属的AS编号应该和本地AS号不同。
所指定的对等体的IPv6地址可以是以下四种：

▪直连对等体的接口IPv6地址；
▪路由可达的对等体的Loopback接口地址；
▪直连对等体的子接口的IPv6地址。

### 8.7 配置BGP4+对等体组

#### 8.7.1 了解BGP4+对等体组

在大型BGP4+网路中，对等体的数目众多，配置和维护极为不便。使用对等体组可以简化管理的难度，还可以提高路由发布效率。根据对等体所在的AS是否相同，对等体组可分为IBGP对等体组和EBGP对等体组。对于EBGP对等体组，根据所包括的对等体是否属于同一个外部AS，又可分为纯EBGP对等体组和混合EBGP对等体组。

● 配置BGP4+的基本功能

背景信息BGP4+有多个IBGP对等体时，配置IBGP对等体组可以简化BGP4+网络的配置和管理。
配置IBGP对等体组不需要指定自治系统号。

### 8.8 配置BGP4+发布路由

#### 8.8.1 了解BGP4+发布路由

BGP4+发布路由时采用如下策略：
● 存在多条有效路由时，BGP4+ Speaker只将最优路由发布给对等体。
● BGP4+ Speaker从EBGP获得的路由会向它所有BGP4+对等体发布（包括EBGP对等体和 IBGP 对等体）。
● BGP4+ Speaker从IBGP获得的路由不向它的IBGP对等体发布。
说明学习路由的对等体和该路由需要发布的对等体，如果两个对等体属于不同地址族，不受此规则限制。
● BGP4+ Speaker从IBGP获得的路由发布给它的EBGP对等体。
● 连接一旦建立，BGP4+ Speaker将把自己所有BGP4+最优路由发布给新对等体。
BGP4+路由表路由数量通常比较大，传递大量的路由对设备来说是一个很大的负担，为了减小路由发送规模，需要对发布的路由进行控制，只发送自己想要发布的路由或者只发布对等体需要的路由。
另外，到达同一个目的地址，可能存在多条路由，这些路由分别需要穿越不同的AS，为了把业务流量引导向某些特定的AS，也需要对发布的路由进行筛选。
使用过滤器可以对BGP4+将要发布的路由进行过滤。BGP4+支持针对某个对等体（组）将要发布的路由信息进行过滤。当同时配置多条过滤策略时，只有所有策略都通过时，BGP4+才会发布相关路由。

#### 8.8.2 配置BGP4+相关访问列表

背景信息BGP4+有两种专有的访问列表：AS路径过滤器和团体属性过滤器，在显示BGP4+运行状态和路由策略中都可以使用。
● AS路径过滤器AS路径过滤器用来匹配BGP4+路由信息的AS_Path属性，过滤掉不符合条件的路由信息。在同一个过滤器编号下，可以定义多条规则（Permit或Deny）。
● 团体属性过滤器BGP4+的团体属性是用来标识一组具有共同性质的路由。利用团体属性可以人为的对路由进行分类，方便对路由进行管理。

### 8.9 配置BGP4+接收路由

#### 8.9.1 了解BGP4+接收路由

BGP4+应用于AS之间传递路由信息，路由的接收直接影响流量的转发。
BGP4+设备可能收到不同对等体发来的到达同一目的网络的路由，为了控制网络流量的转发路径，就需要对BGP4+接收的路由进行筛选。
另外，由于可能会受到服务攻击，BGP4+从对等体接收到任意数量的路由，大量消耗设备资源。无论过量BGP4+路由是因为恶意攻击还是因为某错误配置导致，管理员都必须根据网络规划和设备容量，对运行时所使用的资源进行限制。
使用过滤器可以对BGP4+将要接收的路由进行过滤。BGP4+可以对接收的全局路由信息或者只对某个对等体（组）发来的路由信息进行过滤或使用路由策略。当同时配置多条过滤策略时，只有所有策略都通过时，BGP4+才会接收相关路由。

#### 8.15.1 配置BGP4+路由反射器

### 8.18 配置BGP4+定时器

#### 8.18.1 配置BGP4+对等体存活和保持定时器

前提条件在配置BGP4+对等体存活和保持定时器之前，需完成以下任务：
● 配置BGP4+的基本功能背景信息当对等体间建立了BGP4+连接后，通过定期互发Keepalive消息，确认BGP4+的连接是否正常。若BGP4+设备在设定的连接保持时间（Hold time）内未收到对端的Keepalive消息或任何其他类型的报文，则认为此BGP4+连接已中断，从而中断此BGP4+连接。

须知改变定时器的值（执行peer timer命令）会导致设备之间的对等体关系中断。请仔细确认是否必须改变定时器的值。

### 8.27 配置BGP4+ 6PE

#### 8.27.1 了解BGP4+ 6PE

6PE功能可将被分割的IPv6网络利用MPLS隧道技术连接起来。
产生原因随着IPv6技术的广泛应用，网络中出现了越来越多的IPv6孤岛。对于网络中的运营商来说，无须另外新建IPv6骨干网络，在现有IPv4网络基础上为用户提供IPv6服务就具有重要应用价值，6PE（IPv6 Provider Edge）正是基于这个理念来设计的。6PE是一种在目前的IPv4网络中利用MPLS隧道技术为不同地区的被分割的IPv6网络提供连通服务的解决方案，它是在ISP（Internet Service Provider）的PE上实现IPv4/IPv6双协议栈，利用MP-BGP（Multi-protocol Extensions for Border Gateway Protocol）为其分配的标签标识IPv6路由，从而通过PE之间的IPv4隧道实现IPv6孤岛之间的互通。
说明该配置仅S6780-H、S6750-H、S6750E-S、S6750-S、S6730E-H-V2、S6730-S-V2、S6730-H- V2、S5732-H-V2、S5755-H支持该配置。
相关概念现实网络中，同一运营商的不同城域网之间，或相互协作的运营商的骨干网之间都存在着跨越不同自治域的情况。按照IPv6孤岛所连接的自治域是否相同来划分，6PE可以分为单自治域6PE和跨域6PE。其中对于IPv6孤岛连接到不同自治域的情况，标准协议提出了跨域6PE的实现方式，分别是：OptionB方式的跨域6PE（ASBR兼作PE）和OptionB 方式的跨域 6PE 。
● 单自治域6PE：IPv6孤岛连接到同一个自治域，处于同一个自治域内的PE之间通过MP-IBGP关系传递IPv6路由。
● 跨域6PE：
– OptionB方式的跨域6PE（ASBR兼作PE）：处于不同自治域的ASBR之间通过MP-EBGP关系传递IPv6路由。
– OptionB方式的跨域6PE：处于不同自治域的ASBR之间通过MP-EBGP关系传递IPv6标签路由。
单自治域 6PE图8-4是单自治域6PE组网示意图。6PE要求运行在ISP网络边缘，与用户IPv6网络连接的PE上采用IPv4/IPv6双协议栈，PE和CE之间利用IPv6协议中的EBGP或者IGP交换IPv6

路由。PE和P、其他PE之间利用IPv4路由协议交换路由。PE之间需要创建隧道来透明传输IPv6报文，隧道类型主要有MPLS LSP（Label Switched Path）和MPLS Local Ifnet，缺省情况下，系统优先选择LSP隧道，如果没有LSP隧道，系统会选择MPLS Local Ifnet隧道。
图 8-4 单自治域 6PE 组网图单自治域6PE的路由传递和数据转发过程如图8-5所示，该图表示的是CE2发送路由给CE1，CE1发送报文给CE2的过程。其中，I-L表示内层标签，O-L表示外层隧道标签。
外层隧道标签由MPLS分配，用来指示如何到达BGP下一跳，内层标签表示报文的出接口或者报文属于哪个CE。
单自治域6PE的具体路由传递过程如下：
1. CE2将域内IPv6路由通过EBGP对等体关系传递给PE2；
2. PE2收到CE2发来的IPv6路由后，修改路由的下一跳为自身，并且为IPv6路由分配内层标签，然后将IPv6标签路由通过IBGP对等体关系向PE1发送；
3. PE1收到PE2发来的IPv6标签路由后，为IPv6标签路由迭代隧道，并且将路由信息下发到转发表。然后，PE1修改路由的下一跳为自身，并且去除IPv6路由的标签，然后通过EBGP对等体关系向CE1发送普通IPv6路由。
这样， IPv6 路由就由 CE2 传递到了 CE1 。
单自治域6PE的具体报文转发过程如下：
1. CE1将普通IPv6报文通过公网IPv6链路发送给PE1；
2. PE1收到CE1发来的IPv6报文后，根据报文的目的地址查找转发表，然后为报文封装内层标签和外层隧道标签。封装了两层标签的IPv6报文通过公网隧道被转发给PE2；
3. PE2收到封装了两层标签的IPv6报文后，弹出两层标签，再根据IPv6报文的目的地址将报文通过IPv6链路转发给CE2。
这样， IPv6 报文就由 CE1 传递到了 CE2 。
从路由传递和报文转发过程可以看出，对于设备来说，并不会感知公网是IPv4公网或者是IPv6公网。

### 8.33 配置BGP4+认证

#### 8.33.1 配置BGP4+认证

前提条件在配置BGP4+认证之前，需完成以下任务：
● 配置BGP4+的基本功能背景信息BGP4+认证，包括MD5与Keychain两种认证方式：
MD5认证
●BGP4+使用TCP作为传输协议，只要TCP数据包的源地址、目的地址、源端口、目的端口和TCP序号是正确的，BGP4+就会认为这个数据包有效，但数据包的大部分

参数对于攻击者来说是不难获得的。为了保证BGP4+协议免受攻击，BGP4+邻居之间使用TCP的MD5认证来降低被攻击的可能性。
为防止BGP4+对等体所设置的MD5密码被破解，需要周期性的更新MD5认证密码。
● Keychain认证Keychain由多个认证密钥组成，每个密钥包含一个ID和密码。密钥存在生命期，通过密钥的生命期可以在Keychain中滚动选择不同的认证密钥。BGP4+会话两端绑定相同规则的Keychain后，Keychain可以滚动选择认证密钥来增强BGP4+防攻击性。

BGP4+ MD5认证与BGP4+ Keychain认证互斥。
MD5认证安全性低，为了保证更好的安全性，建议使用Keychain认证，并且使用安全性较高的算法，例如HMAC-SHA-256。

### 8.34 配置BGP4+ GTSM

前提条件在配置BGP4+ GTSM功能之前，需完成以下任务：
● 配置BGP4+的基本功能背景信息GTSM机制通过TTL的检测来达到防止攻击的目的。如果攻击者模拟真实的BGP4+协议报文，对一台BGP4+设备不断的发送报文。BGP4+设备收到这些报文后，发现是发送给本机的报文，则直接上送控制层面的BGP4+协议处理，而不加辨别其“合法性”。
这样导致BGP4+设备控制层面因为处理这些“合法”报文，系统异常繁忙，CPU占用率高。
配置GTSM功能，通过检测IP报文头中的TTL值是否在一个预先定义好的特定范围内来对BGP4+设备进行保护，增强系统的安全性。
说明因为GTSM只支持单播地址，因此需要在路由协议作用范围内的所有设备上部署GTSM。
操作步骤步骤1 进入系统视图system-view步骤2 进入BGP视图。
bgp as-number步骤3 配置BGP4+ GTSM功能。
peer { group-name | ipv6-address } valid-ttl-hops [ hops ]被检测报文的TTL值有效范围为[ 255–hops+1, 255 ]。例如，对于EBGP直连路由，hops的取值为1，即有效的TTL值设为255。缺省情况下，参数hops取值为255，即TTL有效值范围为 [ 1, 255 ]。

说明
● 当在BGP视图下配置时，对MP-BGP的扩展同样有效，因为它们使用同一个TCP连接。
● GTSM和EBGP-MAX-HOP功能均会影响到发送出去的BGP4+报文的TTL值，存在冲突，只能对同一对等体或对等体组使能两种功能中的一种。
使能BGP4+的GTSM策略后，设备对所有BGP4+报文的TTL值进行检查，根据实际组网的需要，对于不符合GTSM策略中指定的TTL值范围的报文，直接丢弃。对于没有配置GTSM策略的报文，如果BGP4+ Peer配置存在，直接上送。没有配置BGP4+ Peer的BGP4+报文直接丢弃。这样就避免了网络攻击者模拟的“合法”BGP4+报文占用CPU。

#### 8.36.4 配置BGP4+优雅降级功能

当设备内存状态处于危险态时，BGP4+可以丢弃从对等体接收到的新路由；若设备内存长时间处于危险态时，BGP4+可以复位进程。
前提条件在配置BGP4+优雅降级功能之前，需完成以下任务：
● 配置BGP4+的基本功能
● 通过memory-usage reliability switch on命令开启内存过载可靠性开关背景信息根据设备内存占用率使用情况，将设备内存分为如下状态：
1. 预警态：指设备内存占用率超过预警阈值（又称通知阈值）时的状态，此阈值缺省值为70，即设备内存占用率超过70%时，设备进入预警态。可以通过memory- usage reliability命令中的notice-threshold notice-threshold-value进行设置。

2. 危险态：指设备内存占用率超过危险阈值（又称过载阈值）时的状态，此阈值缺
省值为85，即设备内存占用率超过85%时，设备进入危险态。可以通过memory-
usage reliability命令中的overload-threshold overload-threshold-value进行设
置。
3. 异常态：指设备内存占用率超过异常阈值时的状态，此阈值缺省值为90，即设备
内存占用率超过90%时，设备进入异常态。可以通过memory-usage reliability
命令中的exception-threshold exception-threshold-value进行设置。
当设备内存状态处于危险态时，如果BGP4+还持续接收新路由，可能会导致设备内存
耗尽，进而导致进程或单板复位，甚至引起整机重启。为了解决这个问题，可以丢弃
从IPv4、IPv6、VPNv4、VPNv6、EVPN对等体接收到的新路由及VPNv4、VPNv6、
EVPN地址族向VPN实例新交叉路由。
如果设备已经使能了设备内存状态处于危险态时BGP4+丢弃从邻居新收到的路由功
能，但设备内存仍长时间处于危险态，BGP4+会尝试和邻居断连再复位所在进程，以
尝试从危险态逃生。
为避免影响关键业务，可以配置邻居在设备内存处于危险态时不断连，保证业务不中
断。
操作步骤

#### 8.37.5 举例：配置BGP4+使用Keychain认证

组网需求如图8-15所示，网络中DeviceA和DeviceB通过BGP4+实现互通。
为了确保BGP4+连接的稳定和安全，配置Keychain为BGP4+提供动态的安全认证服务。
图 8-15 Keychain 组网图说明本例中 interface1 代表 Vlanif100 。

BGP4+对等体两端必须都配置Keychain认证，且配置的Keychain必须使用相同的加密算法和密码，才能正常建立TCP连接，交互BGP4+消息。
配置本例，需要准备以下数据：
● Keychain名称
● Keychain的接收容忍时间
● TCP增强认证选项中的类型值（TCP Kind）和TCP认证的算法ID（TCP algrithm- id）
● Keychain中Key的ID
● Key的认证算法和认证密钥（加密字符串）
● Key的活跃发送时间和活跃接收时间配置注意事项
● 配置本例前，需要提前完成NTP和BGP4+配置。
● DeviceA和DeviceB配置的Keychain名称需要相同。
● DeviceA和DeviceB配置的Keychain的时间模式需要相同。
● DeviceA和DeviceB配置的Keychain的Key的ID需要相同。配置多个Key时，两端都需要配置相同ID的多个Key。
● 对于同一个Key，DeviceA和DeviceB配置的Keychain的Key的认证算法和认证密钥（加密字符串）需要相同。
对于同一个Key，DeviceA和DeviceB配置的Keychain的Key的活跃发送时间和接收
●活跃时间需要对应。例如，DeviceB的活跃接收时间至少需要包含DeviceA的活跃发送时间，以避免丢包。反之亦然。
● 如果Keychain中配置多个Key时，其中只能有1个Key配置为缺省发送key。
● 出于安全性考虑，不建议使用HMAC-SHA-256算法，如果确实需要使用，请先执行命令install feature-software WEAKEA安装弱安全算法/协议特性包WEAKEA。

1. 创建Keychain。
2. 配置Keychain中的Key。
3. 配置BGP4+使用Keychain认证。DeviceA和DeviceB指定密码通过HMAC-SHA256算法加密后参与认证。
