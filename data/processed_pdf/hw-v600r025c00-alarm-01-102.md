### 102.3 VSTM_1.3.6.1.4.1.2011.5.25.145.40.1 hwVstmMacExceed

Trap Buffer 信息解释The number of MAC routes on the device exceeded the maximum value.
(CurrentMACRouteCount=[VstmCurMacNum], MaxMACRouteValue=[VstmMaxMacNum])
设备的MAC路由数量超过最大值。

说明仅S6750-H，S6730E-H-V2，S6750E-S，S6730-S-V2，S5755-H，S6780-H，S5732-H-V2，S6730- H-V2，S5755-S，S6750-S形态支持此告警。

| Trap属性 | 描述 |
|---|---|

| Trap Severity | Error |

| MIB | HUAWEI-RM-EXT-MIB |
| Alarm ID | 0x00F10386/0xF10386 |
| Alarm Severity | Minor |
| Alarm Name | hwVstmMacExceed |
| Alarm Type | qualityOfServiceAlarm |
| Raise or Clear | Raise |
| Match trap | VSTM_1.3.6.1.4.1.2011.5.25.145.40.2 hwVstmMacExceedClear |

Trap Buffer 信息参数

| 参数名称 | 参数含义 |
|---|---|
| VstmCurMacNum | VSTM中当前的MAC地址数量 |
| VstmMaxMacNum | VSTM中MAC地址数量的最大值 |

VB 信息参数

| VB OID | VB Name | VB Index |
|---|---|---|
| 1.3.6.1.4.1.2011.5.25.145. 39.1 | hwVstmCurMacNum | - |
| 1.3.6.1.4.1.2011.5.25.145. 39.2 | hwVstmMaxMacNum | - |

对系统的影响MAC地址数量超过最大值，不能再加入任何MAC。

这个会导致MAC丢失，部分流量不通。
可能原因VSTM中MAC地址数量超过MAC地址数量的最大值。
处理步骤
1.查看MAC表项，检查这些MAC表项是否是用户需要的。
● 如果MAC表项是用户需要的，请执行步骤3。
● 如果MAC表项不是用户需要的，在确保业务不受影响的前提下，请执行步骤2。
2.尝试删除多余的MAC地址，查看设备的MAC地址总数是否减少。
● 如果MAC表项减少，产生了清除告警,请执行步骤4。
● 如果MAC表项没有变化，请执行步骤3。
3. 请收集告警信息和配置信息，并联系技术支持工程师。
结束。
4.
