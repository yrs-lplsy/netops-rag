● 原因2：The cause value was not used.（该原因值针对所有产品已废弃。）

处理步骤
● 原因1：Failed to read the configuration information of the patch package.
1.重新安装补丁包文件。安装完成后，使用display patch-information命令查看补
丁包的状态。
– 如果补丁包的状态为run，则表示补丁包安装成功，此告警问题解决。
– 如果补丁包的状态不为run，则=>2。
2. 请收集日志文件，联系技术支持工程师。
● 原因2：The cause value was not used.
请收集日志文件，联系技术支持工程师。
● 原因3：The memory space of the memory was not enough.
1.使用dir命令查看当前剩余空间大小是否足够：
– 是，则执行步骤3。
– 否，则执行步骤2。
2.清理空间后再重新安装补丁包。安装完成后，使用display patch-information命
令查看补丁包的状态是否为run，即安装是否成功：
– 是，则执行步骤4。
– 否，则执行步骤3。
3.请收集日志文件，联系技术支持工程师。
4.结束。
● 原因4：The patch conflicted with the previous one.
1.卸载当前补丁，再重新安装补丁包。安装完成后，使用display patch-
information命令查看补丁包的状态是否为run，即安装是否成功：
– 是，则执行步骤4。
– 否，则执行步骤2。
2.重启设备，再安装补丁包。安装完成后，使用display patch-information命令查
看补丁包的状态是否为run，即安装是否成功：
– 是，则执行步骤4。
– 否，则执行步骤3。
3.请收集日志文件，联系技术支持工程师。
4.结束。
原因5：The
● patch package version was incorrect.
1. 执行 display startup 查询大包版本号。
2.更换与大包版本匹配的补丁，查看告警是否清除。
– 如果是，则转至步骤4。

– 如果否，则转至步骤3。
3.请收集告警信息和日志信息，联系技术工程师。
4.结束。
● 原因8：Failed to synchronize the patch package file because of insufficient
disk space.
1.执行dir命令查看告警中对应槽位号单板剩余磁盘空间的大小。
如果剩余空间小于当前加载补丁文件大小，则执行delete /unreserved命令删除不
使用文件，清理环境确保拷贝空间足够，则转至步骤2。
如果剩余磁盘空间大于当前加载补丁文件大小，则转至步骤3。
2.再重新执行补丁加载操作，重启对应槽位号单板。
3.请收集告警信息和日志信息，联系技术工程师。
4.结束。
● 原因9：The patch configuration is inconsistent.
存在3种方式消除告警：
1. 告警上报后，主备倒换两次，单板注册半小时后，告警通过老化机制被消除，
如果无法消除，则转至步骤4。
2. 告警上报后，重启单个单板，单板注册半小时后，对应单板上的告警通过老化
机制被消除，如果无法消除，则转至步骤4。
3. 告警上报后，重启设备告警被消除，如果无法消除，则转至步骤4。
4. 请收集日志文件，联系技术支持工程师。
● 原因10：The source file in the patch is abnormal.
请收集告警信息、日志信息和配置信息，联系技术支持工程师。
