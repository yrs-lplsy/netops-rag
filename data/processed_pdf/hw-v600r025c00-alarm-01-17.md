17.1 DLDP_1.3.6.1.4.1.2011.5.25.173.3.1
hwDldpUnidirectionalLink
Trap Buffer 信息解释
Link layer state of the port changed to one way. (IfIndex=[IfIndex],
IfName=[IfName], FaultReason=[FaultReason])
在以下两种情况下检测到单通状态就会发送告警。 - 单邻居的情况：两个设备互连，
其中一个设备可以收到对端设备的报文，但是对端却收不到本端设备发送的报文，这
种链路称之为单向链路，该设备进入单通状态，这个设备就会发送单通告警。 - 多邻
居的情况：某一个设备如果发现它的一个邻居处于单通状态，或者收到disable报文，
该设备就会进入单通状态，该设备会发送单通告警。
Trap 属性

| Trap属性 | 描述 |
|---|---|
| Alarm or Event | Alarm |
| Trap Severity | Critical |
| Trap OID | 1.3.6.1.4.1.2011.5.25.173.3.1 |
| MIB | HUAWEI-DLDP-MIB |
| Alarm ID | 0x09AA0000/0x9AA0000 |
| Alarm Severity | Major |

| Trap属性 | 描述 |
|---|---|
| Alarm Name | hwDldpUnidirectionalLink |
| Alarm Type | communicationsAlarm |
| Raise or Clear | Raise |
| Match trap | DLDP_1.3.6.1.4.1.2011.5.25.173.3.2 hwDldpLinkResume |

Trap Buffer 信息参数

| 参数名称 | 参数含义 |
|---|---|
| IfIndex | 发生单通状态告警的接口索引。 |
| IfName | 发生单通状态告警的接口名称。 |
| FaultReason | 发生故障的原因。 |

VB 信息参数

| VB OID | VB Name | VB Index |
|---|---|---|
| 1.3.6.1.4.1.2011.5.25.173. 2.1 | hwDldpTrapInterfaceInde x | - |
| 1.3.6.1.4.1.2011.5.25.173. 2.2 | hwDldpTrapIfName | - |
| 1.3.6.1.4.1.2011.5.25.173. 2.3 | hwDldpTrapFaultReason | - |

对系统的影响业务无法在单通链路上正常运行。
可能原因
● 原因1：single channel fault（单纤故障）
● 原因2：complect channel fault（光纤交叉连接）
● 原因3：port error loopback（端口错误环回）
● 原因4：control packet（控制报文即disable和link-down导致端口阻塞）
处理步骤
● 原因1：single channel fault

1. 执行display interface <interface-type> <interface-num>命令，检查相邻设备
直连端口物理状态是否为Down。
– 如果为Down，则请执行步骤2。
– 如果不为Down，则请执行步骤5。
2. 检查相邻设备直连端口Rx线是否松动。
– 如果是，则请执行步骤3。
– 如果不是，则请执行步骤5。
将相邻设备直连端口的Rx线重新插上。
3.
4. 查看告警是否恢复。
– 如果告警没有恢复，则请执行步骤5。
– 如果告警恢复，则请执行步骤6。
5. 请收集告警信息和配置信息，并联系技术支持工程师。
6. 结束。
● 原因2：complect channel fault
1. 检查相邻设备直连端口Tx/Rx线是否配对相连。
– 如果不配对，则请执行步骤2。
– 如果配对，则请执行步骤4。
2. 将相邻设备直连端口的Tx/Rx线配对相连。
3. 查看告警是否恢复。
– 如果告警没有恢复，则请执行步骤4。
– 如果告警恢复，则请执行步骤5。
4. 请收集告警信息和配置信息，并联系技术支持工程师。
5. 结束。
● 原因3：port error loopback
1. 检查故障端口Tx线是否直接插入了本端口的Rx口。
– 如果是，则请执行步骤2。
– 如果不是，则请执行步骤4。
2. 将故障端口的Tx/Rx线重新与目标设备相连。
3. 查看告警是否恢复。
– 如果告警没有恢复，则请执行步骤4。
– 如果告警恢复，则请执行步骤5。
4. 请收集告警信息和配置信息，并联系技术支持工程师。
结束。
5.
● 原因4：control packet
1. 执行display dldp命令，检查相邻设备直连端口是否处于disable状态。

– 如果不是，则请执行步骤2。
– 如果是，则请执行步骤3。
2. 在对端设备上执行display interface <interface-type> <interface-num>命令，
查看对端设备接口是否处于物理Down状态。
– 如果是，则请执行步骤4。
– 如果不是，则请执行步骤6。
3. 执行display interface <interface-type> <interface-num>查看对端设备端口的
故障原因，并根据原因处理故障，查看故障端口告警是否恢复。
– 如果告警恢复，则请执行步骤5。
– 如果告警没有恢复，则请执行步骤6。
4. 查看物理链路是否松动。
– 如果是，请重新插拔光纤使其物理Up，并请执行步骤5。
– 如果不是，则请执行步骤6。
5. 查看本端设备告警是否恢复。
– 如果告警没有恢复，则请执行步骤6。
– 如果告警恢复，则请执行步骤7。
6. 请收集告警信息和配置信息，并联系技术支持工程师。
7. 结束。
