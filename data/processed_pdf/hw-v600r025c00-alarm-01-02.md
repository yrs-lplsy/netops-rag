### 2.1 Trap实现原理

概述当设备发生故障或因某些原因导致系统进入不正常的工作状态时，为帮助用户快速感知并定位问题，系统产生事件和告警信息。
● 事件设备中被管理对象发生的任何情况的通称，以日志的形式记录。例如对象的增加、删除、修改、状态改变等。
设备上产生的事件，部分信息会触发Trap，该Trap称为事件Trap，需要用户及时关注或处理。事件Trap没有配对Trap。
● 告警设备运行状态偏离正常情况，可能导致业务异常或设备无法正常工作等，系统检测到故障而产生的通知。该通知需要用户及时关注或处理，且是维护人员了解设备内部运行状态、进行故障定位的重要信息。例如接口状态的改变。
某些故障产生时，触发告警，此时告警状态为active，同时触发故障告警Trap。当触发故障的原因消失后（例如故障恢复），则故障将被清除，告警状态转为cleared，同时触发业务恢复告警Trap。故障告警Trap和业务恢复告警Trap互为配对Trap，统称为告警Trap。
说明告警和事件等内部信息的定义及其级别，对于网管可能会有不同的定义，用户可以重定义。
信息输出设备产生的信息可以向远程终端、控制台、Log缓冲区、日志文件、SNMP代理等方向输出信息。为了便于各个方向信息的输出控制，信息中心定义了10条信息通道，通道

之间独立输出，互不影响。用户可以根据自己的需要配置信息的输出规则，控制不同类别、不同等级的信息从不同的信息通道输出到不同的输出方向，如图2-1所示。

### 2.3 Trap手册内容简介

信息解释Trap Buffer包括两个部分：Trap信息和Trap含义。
● Trap信息：在设备上显示的Trap信息字符串。
● Trap含义：指明该Trap表示什么意思。
Trap 属性Trap属性简介如表2-4所示。
表 2-4 Trap 属性

|---|---|
| Alarm or Event | Trap类型： ● Alarm：告警 ● Event：事件 |
| Trap Severity | 该Trap对应故障对业务的影响程度。 |
| Mnemonic Code | Trap内容的摘要，便于记忆。 |
| Trap OID | MIB文件中定义的对象标识。 |
| MIB | 该Trap所属的MIB文件。 |
| Alarm ID | 网络管理系统NMS（Network Management System）定义的对象标识。格式为最大8位数的十六进制数。其中，0x为十六进制标志符，且字母A-F不区分大小写。为便于描述，Trap手册中统一采用字母大写形式，且同一个Alarm ID提供两种格式。例如，0x0083001B和0x83001B，两者表示同一个Alarm ID。 |
| Alarm Severity | 告警级别。 |
| Alarm Name | 告警名称。 |

| Trap属性 | 描述 |
|---|---|
| Alarm Type | 表示该告警的性质。 ● communicationsAlarm：通讯告警这类告警与信息传送的处理进程有关，包括网元之间、网元与 OS之间或者OS之间的通信失败时产生的相关告警。 ● qualityOfServiceAlarm：业务质量告警这类告警是由于业务质量退化问题而引起的，包括发生拥塞、性能下降、资源占用率高、带宽减小等业务质量降低时产生的告警。 ● processingErrorAlarm：处理出错告警这类告警是由于软件或处理过程错误而引起的，包括软件错误、内存溢出、版本不匹配、程序异常中止等业务处理时产生的告警。 ● equipmentAlarm：设备告警这类告警是由于物理资源故障而引起的，包括电源、风扇、处理器、时钟、输入/输出接口等硬件设备产生的告警。 ● environmentalAlarm：环境告警这类告警是由设备所在地相关的问题而引起的，包括设备所处环境的温度、湿度、通风等不符合设备正常工作要求时产生的告警。说明 Alarm Type仅对告警Trap有效，事件Trap不涉及。 |
| Raise or Clear | 故障产生或故障恢复的标识。 ● Raise：故障产生 ● Clear：故障恢复 ● None：无法严格界定是故障产生还是故障恢复说明 Raise or Clear仅对告警Trap有效，事件Trap不涉及。 |
| Match trap | 产生告警或恢复告警的配对告警信息。说明 Match trap仅对告警Trap有效，事件Trap不涉及。 |

### 2.4 如何通过本手册查询到对应的Trap

本手册描述了告警Trap和事件Trap信息。Trap信息可以通过如下两种方式查看到：
● 通过网络管理系统界面直接查看Trap信息。
● 通过display trapbuffer [ size buffersize ]命令在命令行终端界面查看设备上Trap显示区内的Trap信息。
Trap显示区内的信息与指定的Trap显示条目，即buffersize的大小有关。如果当前Trap 显示区内信息数少于用户指定的显示条目，则在终端界面上显示实际条数的Trap信息。
建议采用如下技巧帮助您更快速的搜索到准确的Trap：

● 由于“Trap OID”唯一标识一条Trap，建议您通过“Trap OID”在手册中进行搜
索，从而快速查找到对应Trap的解释及处理步骤。
对于一条OID相同的Trap，如果Trap触发原因不同，输出信息中通过携带不同的错
误码（如BaseTrapProbableCause）来标识，这时，请通过错误码在手册中进一步
搜索。
● 使用本手册时，请勿携带可变信息进行搜索，例如Trap产生时间、接口编号、进
程编号、设备命名等。
