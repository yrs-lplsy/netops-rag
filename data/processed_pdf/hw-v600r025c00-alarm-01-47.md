### 47.1 L2VPN_1.3.6.1.4.1.2011.5.25.119.1.2.1 hwVplsVcDown

Trap Buffer 信息解释The status of the VPLS VC turned DOWN. (VsiName=[VsiName], PwId=[PwId], RemoteIp=[RemoteIp], PwType=[PwType], HWL2VpnStateChangeReason=[HWL2VpnStateChangeReason], SysUpTime=[SysUpTime], TunnelPolicyName=[TunnelPolicyName])
VPLS VC状态由UP变为Down时触发的告警。
说明仅 S6750-H ， S6730E-H-V2 ， S6750E-S ， S6730-S-V2 ， S5755-H ， S6780-H ， S5732-H-V2 ， S6730- H-V2，S6750-S形态支持此告警。
Trap 属性

| Trap属性 | 描述 |
|---|---|
| Alarm or Event | Alarm |
| Trap Severity | Critical |
| Trap OID | 1.3.6.1.4.1.2011.5.25.119.1.2.1 |
| MIB | HUAWEI-VPLS-EXT-MIB |
| Alarm ID | 0x0D4D0001/0xD4D0001 |
| Alarm Severity | Major |
| Alarm Name | hwVplsVcDown |
| Alarm Type | communicationsAlarm |
| Raise or Clear | Raise |
| Match trap | L2VPN_1.3.6.1.4.1.2011.5.25.119.1.2.2 hwVplsVcUp |

Trap Buffer 信息参数

| 参数名称 | 参数含义 |
|---|---|
| VsiName | VSI的名称。 |
| PwId | PW ID。 |
| RemoteIp | 远端对等体的IP地址。 |

| 参数名称 | 参数含义 |
|---|---|
| PwType | PW的类型。具体情况如下： ● 1: normal ● 2: other |
| HWL2VpnStateChangeReason | VC变化的原因。 |
| SysUpTime | 系统启动时间。 |
| TunnelPolicyName | 隧道策略名称。 |

| 1.3.6.1.4.1.2011.5.25.119. 1.1.8 | hwVplsStateChangeReas on | - |

对系统的影响对应VPLS业务中断，流量不通。
可能原因
● 原因 1 ： Invalid reason type. （未知原因。）
● 原因3：VC was deleted.（VC删除。）
● 原因4：LDP session was Down.（LDP会话断开。）
● 原因6：Same LDP mapping was received with different label and MTU.（相同的LDP Mapping不同的label和MTU。）
● 原因8：LDP mapping was received with mismatching interface parameters.
（LDP mapping接口参数不匹配。）
● 原因12：New LDP mapping message was received but remote VC or local VC is Down. （收到新的 mapping 消息，但是远端 vc 跟本地 vc 是 down 的。）
● 原因13：LDP withdraw message was received.（收到ldp whitdraw信令。）
● 原因19：Interface was Down.（接口Down。）

● 原因20：Encapsulation changed.（封装类型改变。）
● 原因24：Tunnel was Down.（隧道Down。）
● 原因31：LDP notification message was not forwarded.（收到LDP notification
信令，PW变为不可转发状态。）
● 原因32：PW was recreated.（重建PW。）
● 原因37：Local AC fault.（本地AC口不可用。）
● 原因41：Local PSN Fault.（本地PSN不可用。）
● 原因60：MTU Unmatched.（MTU不匹配。）
● 原因61：VSI was shuted.（VSI实例下使能shutdown。）
● 原因64：Undo set Admin VSI.（VSI实例由管理VSI变为普通VSI。）
● 原因94：PW token exceed.（PW token资源超限。）
● 原因98：Related EVPN Inclusive Multicast route is valid.（EVPN路径有效。）
处理步骤
● 原因 1 ： Invalid reason type.
请收集告警信息和配置信息，并联系技术支持工程师。
● 原因3：VC was deleted.
1. 查看并判断该VPLS VC是否确实要被删除。
– 如果是，则请执行步骤4。
– 如果不是，则请执行步骤2。
2. 重新建立VPLS VC连接，查看告警是否恢复。
– 如果是，则请执行步骤4。
– 如果不是，则请执行步骤3。
3. 请收集告警信息和配置信息，并联系技术支持工程师。
4. 结束。
● 原因4：LDP session was Down.
1. 使用display mpls ldp session命令查看到对端peer的session状态是否是
Operational。
– 如果是，则请执行步骤3。
– 如果不是，则请执行步骤2。
2. 重新建立LDP会话，查看告警是否恢复。
– 如果是，则请执行步骤4。
– 如果不是，则请执行步骤3。
3. 请收集告警信息和配置信息，并联系技术支持工程师。
4. 结束。
● 原因6：Same LDP mapping was received with different label and MTU.
1. 使用reset pw命令重新建立本端PW，查看告警是否恢复。

– 如果是，则请执行步骤3。
– 如果不是，则请执行步骤2。
2. 请收集告警信息和配置信息，并联系技术支持工程师。
3. 结束。
● 原因8：LDP mapping was received with mismatching interface parameters.
1. 使用display vsi verbose命令查看本端和对端PW配置的MTU值是否相同。
– 如果是，则请执行步骤3。
– 如果不是，则请执行步骤2。
2. 重新配置MTU值为一致。查看告警是否恢复。
– 如果是，则请执行步骤4。
– 如果不是，则请执行步骤3。
